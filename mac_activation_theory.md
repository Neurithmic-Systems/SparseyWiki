We will explain the logic for determining when a mac activates in the three different run modes.  As a general note, in any mode (learning, recognition, and recall), we process the current frame of an input sequence (or just the current input in the case of purely spatial inputs, e.g., images) starting at the lowest level nodes of the DAG, i.e., at the sensory input regions (of which there may be an arbitrary number), and then moving up through successively higher DAG levels in level-wise fashion.

As a second general note, when we say that a mac **activates**, we mean that a code [i.e., a **sparse distributed code** (SDC)], which is a **set** of *Q* binary units, one in each of the mac's *Q* WTA **competitive modules** (CMs), is chosen, meaning that those *Q* units are set to "1" (active).  In general, the code chosen on frame *t*+1 can be the same as or have any intersection with the code that was active on frame *t*.  

## Learning mode:

A mac is eligible to activate if it is currently inactive.  When a mac activates, it (i.e., the active code within it) remains active for all the frames of its persistence period.  At the beginning of the frame following the last frame of an active mac's persistence period (i.e., before we present the current frame's input, and thus before we do any propagation of signals in the DAG, or anything else), the mac is set back to being inactive. Then two steps are carried out to see if the mac will activate.

1. the conditions in all of the mac's afferent bundles (U bundles, H bundles, and D bundles) are determined. In particular, for each afferent bundle, the number, &pi;, of active **non-muddled features** in the source region of that bundle is determined. If &pi; is within that bundle's parametrically assigned bounds, then that bundle is said to meet criterion.
2. the number of afferent U bundles that meet criterion is determined.  If that number meets a second criterion, then that mac will activate on the current frame. The second criterion has two settings, "All" and "Any", which is determined by the NDF parameter, **"Multi_Aff_U_Bundle_MacActivationPolicy"**.  If it is set to "All", then the mac will activate only if **all** of its U bundles meet their respective &pi;-criteria.  If it is set to "Any", then the mac will activate if **at least one** of its U bundles meets its &pi;-criterion.

If the mac will activate on the current frame, we then "pull" the synaptic signals via **all active afferent synapses** in **all** criterion-meeting aff bundles. That "pull" process computes the total normalized input, within each aff bundle, to each of the mac's cells. For each cell, it's total normalized input, *V*, resulting from the combination of its normalized input from each of its criterion-meeting afferent bundles, is computed.  The combination is multiplicative, but there are some details to be described shortly. 

Once the "V" values of all the mac's units are computed, the code selection algorithm then runs, resulting in the activation of the mac's code for the current frame.  

So we have to explain the two criteria mentioned above. The first concerns a single afferent bundle.  In general, the source field of an afferent bundle will consist of a set of features.  If the source field is an input field, then those features are binary.  If the source field is an internal field (region), then the "features" are macs, or rather are any of the possible codes that become active in a mac.  That is, the code active in a mac that is afferent to another "target" mac is considered to represent a feature.  In this case, i.e., where a feature is represented by the code active in a mac, it is possible that that code is extremely noisy, i.e., that it does not clearly represent one particular feature, but rather that it represents, approximately equally strongly, several features.  If the number of features that are approximately equally well represented by the code is higher than a parametrically set value, then we say that that source mac (the one in which that code is active) is muddled.
