So we will be explaining the logic for determining when a mac activates in the three different run modes.

Learning mode:

A mac is eligible to activate if it is currently inactive.  An active mac remains active for all the frames of its persistence period.  At the beginning of the frame following the last frame of an active mac's persistence period, it is set back to being inactive. Then the conditions in all of the mac's afferent bundles are determined. In particular, for each afferent bundle, the number, &pi;, of active non-muddled features in the source region of that bundle is determined. If &pi; is within that bundle's parametrically assigned bounds, then that bundle is said to meet criterion.  Then the number of aff U bundles that meet criterion is determined.  If that number meets another criterion, then that mac will activate on the current frame.  Once that determination is made, i.e., that the mac will activate, we then "pull" the synaptic signals via all afferent synapses in all criterion-meeting aff bundles. That "pull" process computes the total normalized input, within each aff bundle, to each of the mac's cells. For each cell, it's total normalized input, V, from all its criterion-meeting afferent bundles is computed.  The code selection algorithm then runs, resulting in activation of a code.  

So we have to explain the two criteria mentioned above. The first concerns a single afferent bundle.  In general, the source field of an afferent bundle will consist of a set of features.  If the source field is an input field, then those features are binary.  If the source field is an internal field (region), then the "features" are macs, or rather are any of the possible codes that become active in a mac.  That is, the code active in a mac that is afferent to another "target" mac is considered to represent a feature.  In this case, i.e., where a feature is represented by the code active in a mac, it is possible that that code is extremely noisy, i.e., that it does not clearly represent one particular feature, but rather that it represents, approximately equally strongly, several features.  If the number of features that are approximately equally well represented by the code is higher than a parametrically set value, then we say that that source mac (the one in which that code is active) is muddled.
